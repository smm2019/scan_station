# WMAS 消息推送中心（局域网独立服务）部署说明 · ㉖v291

把消息推送从"终端轮询"升级为"服务端主动推"：scan_station 产生通知 → 转发本服务 → 本服务用 SSE 实时扇出给网页/PDA 消息中心，与手机 App 系统通知对齐（同源同口径）。

## 一、文件清单（复制这两样到服务器）

| 文件 | 作用 |
|---|---|
| `push_server.js` | 推送中心本体（零依赖单文件，Node 直接跑） |
| `install_push.cmd` | 一键注册成 Windows 服务（常驻+开机自启+崩溃自拉起） |

目标机器：局域网内任一台 Windows（如你截图的 WIN-0HFU28FN5NH / Server 2022），**不需要**和 scan_station 同机。

## 二、部署步骤（5 分钟）

1. **装 Node.js**（已装跳过）：`winget install OpenJS.NodeJS.LTS`，或官网 LTS 安装包。验证：`node -v` ≥ 16。
2. **建目录**：`C:\wmas-push\`，把 `push_server.js` 放进去。
3. **设置密钥（可选但建议）**：与 scan_station 参数面板「消息推送密钥」填同一个值。不设则局域网内任何人可连（内部工具可接受，但建议设）。
4. **注册服务**（管理员 CMD）：
   ```
   C:\wmas-push\install_push.cmd
   ```
   脚本会用 nssm 注册 `WmasPushHub` 服务（Automatic 自启 + 崩溃 2 秒自拉起）。没有 nssm 也没关系，脚本会提示手动命令。
5. **防火墙放行**：TCP 8100 入站（脚本自动加规则；改端口则同步改）。
6. **验证**：浏览器开 `http://本机IP:8100/health`，看到 `{"ok":true,"svc":"wmas-push-hub"...}` 即成功。

## 三、scan_station 侧开关（参数面板 → 消息推送组）

| 参数 | 默认 | 说明 |
|---|---|---|
| 消息推送中心开关 | **0=关** | 1=启用转发+两端 SSE；0=两端回退既有轮询（行为同旧版）。**即时生效，不用重启** |
| 推送中心地址 | 空 | 填 `http://<服务器IP>:8100`。留空=即使开关开也不转发 |
| 推送中心密钥 | 空 | 与服务器 PUSH_KEY 一致 |

开关关掉后：网页/PDA 自动回退 45 秒/30 秒轮询，消息中心照常可用（只是不实时）。推送中心宕机但开关开着：scan_station 转发失败静默降级（5 分钟限频留痕一次），两端 SSE 连不上也自动回退轮询——**任何情况下业务不受影响**。

## 四、对齐口径（与手机 App 消息一致）

- 消息对象 = scan_station `db.notifications` 行原样转发（`{id,to,type,text,time,read,reqId}`），不改一字 → 网页/PDA/App 三端看到的是同一条消息。
- `to` = 目标用户 id 或 `all`；终端按自己 userId 过滤，与 App 系统通知同白名单同口径。
- 推送中心带 500 条环形缓冲：网页/PDA 晚开或重连时按 `since` 补发，**不漏消息**（对齐"App 收到过但网页刚打开也要看到"）。

## 五、排查命令

```
:: 看推送中心在线客户端数/累计转发
curl http://127.0.0.1:8100/stats
:: 看服务状态
sc query WmasPushHub
:: 手动前台跑（调试，Ctrl+C 退出）
node C:\wmas-push\push_server.js
```

## 六、已知边界（如实说明）

- SSE 走 HTTP 长连接，若局域网有代理/防火墙掐空闲连接，服务已带 25 秒心跳保活；仍被掐时两端自动重连（retry:5s）+ 补漏，消息不丢。
- 推送中心只做转发扇出，**不存业务数据**——消息权威仍在 scan_station 数据库，推送中心重启不丢历史（历史走各端既有 history 接口）。
- 手机 App 的系统通知（横幅/铃声）仍由 PDA 本地 flutter_local_notifications 发（系统级通知无法由网页服务代发）；推送中心负责的是**消息内容秒级到达消息中心**，与 App 通知同源同条，不会多也不会少。
